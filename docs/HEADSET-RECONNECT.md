# Переподключение гарнитуры 2021

После внедрения автоматического обнаружения пользователь подтвердил работу
двух гарнитур и геймпада одновременно. Однако старая гарнитура с зелёной рамкой
после выключения/включения искала подключение и требовала нового сопряжения.
После исключения точной USB-команды POWER mode 6 получен первый успешный
возврат без нового сопряжения. Механизм изменения памяти гарнитуры не доказан;
само отсутствие association в прежних тестах не доказывало потерю пары.

## Проверено 15.10.2026

- Возврат адаптера на исходный канал 165 не восстановил обычное подключение
  после включения гарнитуры.
- Диагностический перебор всех 12 каналов при выключенном новом сопряжении
  тоже не дал подключения. Сканирование разрешено только с пустой таблицей
  клиентов, останавливается на association и не принимает новые pair requests.
- При перезапуске самого моста включённая старая гарнитура может повторно
  ассоциироваться. Это не эквивалент её собственному выключению/включению.
- Windows посылает parent GIP POWER (0x05), mode=6, payload length=15:
  `06 00 00 00 00 00 00 55 53 00 00 00 00 00 00`.
  Декодируются только POWER-команды; аутентификация и PCM не записываются.

В [исходном xpad](https://github.com/torvalds/linux/blob/master/drivers/input/joystick/xpad.c)
есть USB init command POWER/mode 6 для некоторых Xbox-геймпадов после Bluetooth.
Это основание для эксперимента, а не спецификация поведения Xbox Headset.
Назначение дополнительных параметров и связь с сохранением радиопары пока
не доказаны. Гарнитура физически работает по RF, Windows видит виртуальный USB;
команды USB-драйвера тем не менее могут менять внутренний режим гарнитуры.

## Узкий эксперимент

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Run-UsbGipAuto.ps1 -IdleChannelScan -PreserveOldWirelessMode
```

Перед изменением флагов остановите текущий мост через `Run-UsbGip.ps1 -Stop`.
Поиск каналов `IdleChannelScan` по умолчанию выключен. После успешного первого
возврата сохранение режима для старой модели включено в автоматическом режиме
по умолчанию. Для диагностического отката используется
`-PreserveOldWirelessMode:$false` (в Python CLI — `--forward-old-usb-mode`).
Legacy fixed-route режим сохраняет прежнюю передачу команд.

`PreserveOldWirelessMode` применяется только после обнаружения модели 0b17
(включая её RF alias 0b31). Он поглощает два точных 15-байтовых шаблона mode 6:
наблюдавшийся выше и вариант с нулевыми параметрами. Только parent command,
без chunk и без запроса GIP ACK. Команда считается обработанной на границе
USB/RF и отражается отдельным счётчиком `UsbModeSwitchSuppressed`; это не
заявление, что команда была передана в радио. Остальные команды, включая auth,
пересылаются с прежней проверкой реального TX. В смешанном USB transfer
сохраняется порядок оставшихся команд и исходная ошибка их передачи.

Неизвестные варианты mode 6, команды дочерних клиентов и варианты с GIP ACK
не поглощаются. Новая гарнитура и геймпад сохраняют прежнюю передачу команд.
Менеджер не включает локальный CCMP и не подменяет результаты аутентификации.

Аппаратно подтверждены `UsbModeSwitchSuppressed=1` и продолжающийся обмен
аудиопакетами. После нового сопряжения с фильтром пользователь выключил
гарнитуру на пять секунд и включил обычным нажатием: она вернулась сама.
В журнале после DISCONNECTED присутствует новая ASSOCIATED без нового pair
request; USBIP создал новый worker с тем же USB-серийником. Менеджер остался
работать без ошибки. Снимок: `work/usbip-green-reconnect-first-proof.json`.
Первая проверка использовала поиск каналов. Затем пользователь сообщил, что
все три устройства вернулись при совместной проверке; состояние подтверждает
три Ready=true на канале 11. Во втором окне журнал не содержит отдельного
DISCONNECTED/ASSOCIATED старой гарнитуры: независимое подтверждение ещё одного
полного выключения ограничено. Качество звука в этом ответе отдельно не
подтверждено. Снимок: `work/usbip-green-reconnect-three-device-proof.json`.

Программные тесты проверяют точные формы команды, неизменность остальных
пакетов, отсутствие захвата auth, сохранение ошибки реального RF TX и выбор
эксперимента только для старой модели в отдельных worker-процессах.
