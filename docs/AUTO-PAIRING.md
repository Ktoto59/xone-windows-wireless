# Автоматическое сопряжение USBIP

Режим `python-auto` обнаруживает устройства по радиосвязи. Предварительно
заполнять MAC или выбирать модель не требуется. Физический адаптер должен уже
работать через WinUSB; эта команда не переключает драйверы.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Run-UsbGip.ps1 -Automatic
```

Для нового сопряжения нажмите кнопку адаптера и переведите устройство в режим
сопряжения. Кнопка открывает 30-секундное окно. Автоматическое возвращение уже
сопряжённых устройств зависит от завершения их радиосопряжения; ограничение
старой гарнитуры описано ниже. `-PairOnStart` дополнительно открывает такое окно
сразу после запуска моста.

Остановка: `Run-UsbGip.ps1 -Stop`. Для возврата к фиксированным адресам после
остановки можно использовать прежний запуск без `-Automatic`.

## Поддерживаемые профили

| Радиоидентичность Microsoft | Виртуальный USB-профиль |
| --- | --- |
| 045e:0b32 | Headset 2024, 0b32 |
| 045e:0b17 / 0b31 | Headset 2021, 0b17 |
| 045e:0b12 / 0b13 | Series Controller, 0b12 |

Это автоматический выбор **из проверенных профилей**, а не обещание поддержки
всех Xbox-совместимых устройств и будущих ревизий. Неизвестная модель получает
`RejectedReason`; USB-устройство с выдуманными дескрипторами не создаётся.

## Экземпляры, сохранение и изоляция

Политики моделей вынесены в отдельные коннекторы в `src/device_connectors`:

| Коннектор | USB-профиль | Render budget | Аудиочасы | USB POWER mode 6 |
| --- | --- | --- | --- | --- |
| `headset_2021.py` | 0b17 | 96 мс | Независимые, 8 мс | Только известные формы поглощаются |
| `headset_2024.py` | 0b32 | 64 мс | Прежний темп входящего RF | Без изменений |
| `series_controller.py` | 0b12 | Аудио не включается | Не используются | Без изменений |

Конфигурации неизменяемы; worker выбирает коннектор один раз по announce.
Текущее имя доступно в поле `Connector`. Общими остаются проверенный кодек
GIP/USBIP и физическое радио. Настройки старой модели не применяются к новой.
Render budget ограничивает срок ожидания; это не постоянная добавленная задержка.

- Отдельный процесс USBIP запускается по факту радиоподключения. Пустые слоты
  занимают только localhost listeners, без отдельных Python-процессов.
- Модель выбирается по parent GIP announce до разрешения USBIP import.
- Каждый экземпляр получает стабильный USB-серийник из модели и адреса.
  Два устройства одной модели не используют общий серийник или PCM-буфер.
  При первом переходе с фиксированного режима Windows создаёт новые экземпляры
  устройств; при необходимости выберите их в настройках вывода звука.
- Каждый radio association использует новое прямое соединение C++ -> worker.
  Удаление соединения уничтожает его старые запросы перед переиспользованием
  слота/WCID. Аудио не ретранслируется через управляющий процесс.
- Старая гарнитура сохраняет независимые аудиочасы, новая — ранее проверенный
  режим. Управляющий менеджер не меняет формат PCM или аутентификацию.
- Реестр `config/paired-devices.local.json` записывается автоматически и
  исключён из Git вместе с временными файлами. Список содержит обнаруженные
  модели/адреса/серийники; это не ключи аутентификации и не ручной allowlist.
- При отключении удаляется только выделенный этим запуском USBIP-порт,
  завершается только соответствующий worker. Другие устройства продолжают
  работать. Реестр хранит до 256 обнаруженных устройств.
- Потеря RF явно закрывает USB-сокеты и задачи только соответствующего worker,
  даже если Windows ещё держит import открытым. Новый radio association в
  повторно выделенном слоте может завершить зависший предыдущий worker этого
  слота; соседние процессы и порты не затрагиваются. Это важно и при смене
  типа устройства в слоте, например 2021 -> 2024.

По умолчанию выделено 8 одновременных слотов. `Run-UsbGipAuto.ps1 -Slots N`
поддерживает 1..16. Число слотов — ограничение ресурсов программы, а не
подтверждение пропускной способности для такого числа гарнитур.

## Ограничения первой реализации

- Для старой гарнитуры по умолчанию поглощается точная наблюдавшаяся команда
  USB POWER mode 6. После нового сопряжения с этой адаптацией подтверждено
  возвращение после выключения/включения без pair request. Для уже затронутой
  гарнитуры может понадобиться одно новое сопряжение. Два поддерживаемых
  шаблона, диагностический откат и границы проверки описаны в
  [HEADSET-RECONNECT.md](HEADSET-RECONNECT.md). Это исправление проверенной
  формы команды; неизвестные параметры и другие модели не изменяются.
- Перебор радиоканалов выполняется только при пустой таблице радиоклиентов.
  При активных клиентах сопряжение пробуется на текущем канале, а состояние
  `PairingScanDeferred=true` объясняет отложенный поиск. Бесшовный поиск нового
  канала с продолжающимся звуком ещё не реализован; существующий звук ради
  поиска принудительно не обрывается.
- Сбой отдельного worker изолируется от соседних устройств. После ошибки
  маршрута может потребоваться выключить/включить соответствующее устройство.
- Качество нескольких физических экземпляров одной модели требует отдельного
  аппаратного теста. Программные тесты проверяют два настоящих worker-процесса,
  TCP и USBIP-дескрипторы, но не заменяют два физических устройства.
- Это ещё не установщик/служба Windows и не автоматическое восстановление
  физического адаптера после его извлечения. Повторный запуск после отключения
  адаптера выполняется отдельно.

## Проверки

`python scripts/Test-UsbGip.py` включает тесты автоматического режима:
неизвестные модели, разные серийники одинаковых моделей, обязательность
согласованной сохранённой идентичности, передача TCP-сокета новому процессу,
USBIP import и чтение реального string descriptor, локальное отключение,
сохранение реестра и повторное подключение с тем же серийником.

`tests/auto_gip_router_tests.cpp` проверяет чередование, одинаковые completion
tokens разных устройств, уничтожение старой очереди при повторном WCID,
переполнение пула и изоляцию сбоя соседа. Запускается из `scripts/build.cmd`.

15.10.2026 пользователь подтвердил одновременное подключение гарнитур 2021/2024
и Series Controller без ручного списка адресов, чистый звук в обеих гарнитурах
и возвращение геймпада после выключения/включения. Это проверка конкретных трёх
устройств, а не подтверждение всех сценариев сопряжения. При последующем
выключении старой гарнитуры обнаружена гонка: VHCI уже удалил порт после EOF,
а повторный detach завершал весь менеджер. Обработка теперь проверяет список
портов и считает удаление завершённым только при подтверждённом отсутствии
порта; наличие порта или ошибка проверки не маскируются.

Позднее после выключения устройств старая задача USBIP оставалась жива,
сохраняла устаревшее Ready=true и задерживала следующее устройство в том же
слоте. Новая гарнитура ассоциировалась по RF, но её worker не запускался.
Исправлены закрытие активных imports на RF EOF и замена зависшего владельца
слота. Тест оставляет настоящий USBIP import открытым, разрывает RF и требует
завершения worker за три секунды при живом соседе. Отдельно проверяется
замена зависшего процесса без удаления порта соседа.

После исправления и выключения диагностического поиска пользователь подтвердил:
новая гарнитура подключилась сама, звук нормальный. В снимке новой ревизии:
Ready=true, Connector=headset-2024, фильтр mode 6 выключен, RX/TX=5343/5341,
render expiry=0 и capture drops=0. Это короткое окно, не длительный стресс-тест.
`work/usbip-new-after-connectors-and-cleanup.json`; 95 Python-тестов прошли.
